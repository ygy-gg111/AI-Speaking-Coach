# 3. 产品架构与页面信息架构设计

## 3.1 本章目标

本章定义 AI Speaking Coach 的产品页面结构、导航体系、核心页面布局、页面之间的关系以及 PC 与移动端的响应式规则。

设计目标：

1. PC 端作为主要使用场景。
2. 移动端保持完整可用，而不是简单缩小 PC 页面。
3. 对话练习页面突出沉浸感。
4. 学习数据和纠错信息不能干扰主对话。
5. 用户能够快速进入练习。
6. 用户能够方便地复习收藏场景、错误和词汇。
7. 整体信息架构能够支撑后续语音、课程和订阅功能。

产品页面围绕三条核心路径设计：

```text
开始练习
复习内容
查看成长
```

## 3.3 导航架构

PC 端采用左侧固定导航栏。

推荐一级导航：

```text
首页
场景练习
我的场景
错误本
单词本
学习日历
学习报告
设置
```

导航优先级：

| 导航项   | 优先级 | 说明                     |
| -------- | ------ | ------------------------ |
| 首页     | P0     | 用户进入系统后的默认页面 |
| 场景练习 | P0     | 产品最核心入口           |
| 我的场景 | P0     | 收藏和重复练习入口       |
| 错误本   | P0     | 学习闭环核心             |
| 单词本   | P1     | 场景词汇复习             |
| 学习日历 | P1     | 打卡和历史记录           |
| 学习报告 | P1     | 数据成长反馈             |
| 设置     | P2     | 账户和偏好配置           |

移动端底部导航不建议放置全部功能。

推荐底部导航：

```text
首页
场景
练习
复习
我的
```

其中：

- 首页：Dashboard。
- 场景：场景列表。
- 练习：最近练习或快速开始。
- 复习：错误本和单词本入口。
- 我的：日历、报告、设置。

## 3.4 PC 页面整体布局

PC 端采用响应式三栏布局。

```text
┌──────────────┬──────────────────────────────┬────────────────────┐
│              │                              │                    │
│   Sidebar    │         Main Content         │   Context Panel    │
│              │                              │                    │
│   240px      │        Flexible Width        │      320px         │
│              │                              │                    │
└──────────────┴──────────────────────────────┴────────────────────┘
```

推荐宽度：

```text
Sidebar：220px 至 248px
Main Content：自适应
Right Panel：300px 至 360px
最大内容宽度：1600px
```

适用页面：

- 首页
- 对话练习
- 场景详情
- 学习报告
- 错误本
- 日历详情

右侧 Context Panel 根据页面变化。

例如：

首页：

```text
今日目标
连续打卡
快速开始
```

对话页：

```text
当前场景
学习进度
本轮提示
纠错摘要
```

错误本：

```text
错误类型统计
复习计划
掌握趋势
```

## 3.5 响应式断点设计

推荐断点：

```text
Mobile：< 768px
Tablet：768px 至 1199px
Desktop：1200px 至 1599px
Large Desktop：≥ 1600px
```

### Mobile

```text
隐藏左侧 Sidebar
隐藏固定右侧面板
使用底部导航
右侧内容改为 Drawer 或 Bottom Sheet
主内容占满宽度
```

### Tablet

```text
Sidebar 收缩为图标导航
右侧面板默认隐藏
点击按钮展开 Drawer
主内容占据主要空间
```

### Desktop

```text
完整 Sidebar
主内容区
固定或可收起右侧面板
```

### Large Desktop

```text
保持三栏
限制内容最大宽度
增加留白
避免对话区域过宽
```

## 3.7 首页 Dashboard

首页目标：

```text
让用户在 10 秒内决定今天练什么
```

首页不应堆积过多数据。

推荐布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 欢迎语 + 今日学习状态                                         │
├─────────────────────────────────────┬────────────────────────┤
│ 今日推荐场景                        │ 今日目标                │
│                                     │ 连续打卡                │
├─────────────────────────────────────┼────────────────────────┤
│ 最近练习                            │ 本周数据                │
├─────────────────────────────────────┴────────────────────────┤
│ 场景分类                                                   │
└──────────────────────────────────────────────────────────────┘
```

### 首页模块

#### 1. 欢迎区域

显示：

- 用户昵称
- 今日日期
- 当前连续打卡天数
- 今日学习完成情况

示例：

```text
下午好，冠尧。

今天完成一个 10 分钟场景，就算打卡成功。
```

避免过度鸡汤。

------

#### 2. 今日推荐场景

推荐依据：

- 用户最近练习
- 用户目标
- 常见错误
- 收藏场景
- 未完成场景
- 学习间隔

卡片内容：

```text
场景名称
角色
难度
预计时长
训练重点
开始练习
```

示例：

```text
酒店办理入住

角色：酒店前台
难度：A2
时长：8 分钟
重点：预订、证件、房型表达
```

------

#### 3. 最近练习

显示最近 3 至 5 次练习。

字段：

```text
场景
时间
完成度
错误数量
继续练习
查看总结
```

------

#### 4. 今日目标

显示：

```text
计划练习时间
已完成时间
计划场景数
已完成场景数
```

MVP 不需要复杂目标系统。

默认目标：

```text
每天 10 分钟
每天 1 个场景
```

------

#### 5. 本周数据

显示：

```text
学习时长
完成场景
新学表达
纠正错误
```

不建议首页出现复杂图表。

------

#### 6. 快速开始

提供：

```text
继续上次练习
随机场景
收藏场景
最常用场景
```

## 3.10 对话练习页

对话练习页是产品最重要的页面。

设计目标：

```text
用户注意力始终放在“说下一句”上
```

PC 推荐三栏结构：

```text
┌──────────────┬──────────────────────────────┬────────────────────┐
│ 场景信息     │ 对话区域                     │ AI学习面板         │
│              │                              │                    │
│ 当前步骤     │ AI消息                       │ 当前目标           │
│ 进度         │ 用户消息                     │ 提示               │
│ 退出         │ 输入区                       │ 纠错               │
│              │                              │ 新词               │
└──────────────┴──────────────────────────────┴────────────────────┘
```

也可以复用全局 Sidebar，将场景信息放在对话页顶部。

### 对话页核心区域

包括：

1. 场景标题。
2. AI 角色。
3. 当前步骤。
4. 进度条。
5. 消息列表。
6. 实时语音连接与麦克风控制。
7. 实时字幕。
8. 文本输入降级入口。
9. 提示按钮。
10. 结束练习。
11. AI 反馈面板。

------

### 对话消息结构

AI 消息：

```text
角色头像
角色名称
英语内容
播放按钮
慢速播放
中文解释开关
```

用户消息：

```text
用户内容
语音播放
识别文本
纠错状态
重新回答
```

不建议默认显示每句中文翻译。

推荐：

```text
用户点击后显示
```

否则用户容易一直依赖中文。

------

### 输入区域

PC：

```text
开始/结束实时通话
麦克风开关
实时字幕
文本输入框（降级）
提示按钮
```

移动端：

```text
大号实时通话按钮
麦克风开关
实时字幕
文本输入入口（降级）
提示按钮
```

输入框状态：

```text
等待输入
正在连接
正在聆听
用户正在说话
AI正在思考
AI正在说话
用户打断AI
正在重连
连接失败
```

默认启用 VAD 自动识别用户开始和结束说话。用户在 AI 播放过程中再次说话时，系统必须立即停止未播放音频，并将本轮状态切换为用户输入。

------

### AI 等待状态

不要只显示普通 Loading。

推荐显示：

```text
机场工作人员正在回应……
```

或者：

```text
AI老师正在听你的表达……
```

保持场景沉浸感。

------

### 纠错展示策略

纠错不能在用户消息下方直接显示大段红色错误。

推荐分为两层。

第一层：

```text
轻提示
```

例如用户消息右上角显示：

```text
1 处可以更自然
```

第二层：

点击后在右侧面板展示：

```text
你的表达
推荐表达
自然说法
原因
重新练习
```

这样既不会打断交流，也保留学习价值。

------

### 提示展示

提示按钮状态：

```text
提示 1
提示 2
参考答案
```

首次点击：

```text
关键词
```

第二次点击：

```text
句型
```

第三次点击：

```text
完整表达
```

完整答案展示后，推荐出现：

```text
跟读一次
自己再说一次
```

不能只让用户看答案后继续下一步。

------

### 当前目标

右侧面板显示：

```text
当前任务：
告诉工作人员你的目的地。
```

避免用户忘记当前场景目标。

------

### 对话结束

以下情况结束：

```text
完成所有场景步骤
用户主动结束
达到最大轮数
长时间无操作
场景异常中止
```

用户主动结束时弹出：

```text
结束并生成总结
暂时离开
继续练习
```

```text
对话轮数

错误数量
学到的表达
需要改进
重新练习

```

```text
┌──────────────────────────────────────────────────────────────┐

│ 酒店办理入住 · 9分32秒                                       │

```

## 3.12 我的场景

“我的场景”用于承载用户和场景之间的长期关系。

包含四个 Tab：

```text
收藏
最近练习
已完成
自定义
```

### 收藏场景

用户可以：

- 快速开始。
- 播放标准对话。
- 查看高频表达。
- 查看历史错误。
- 再次练习。

### 最近练习

按最近时间排序。

显示：

```text
最后练习时间
历史完成次数
最佳完成度
最近错误
继续练习
```

### 已完成场景

帮助用户看到积累。

### 自定义场景

V2 功能。

用户输入：

```text
我下周要参加一个英文家长会
```

系统生成对应场景。

MVP 页面可以保留入口，但标记为：

```text
即将上线
```

## 3.13 场景复听模式

收藏场景除了再次练习，还需要支持“复听”。

这是产品与普通聊天工具的重要差异。

用户可选择：

```text
完整对话
逐句播放
慢速播放
中英对照
只听英文
跟读模式
```

页面结构：

```text
场景标题
角色对话列表
播放控制
语速控制
中英切换
跟读按钮
开始实战
```

复听内容来源：

1. 官方标准场景对话。
2. 用户历史练习对话。
3. AI 根据用户错误生成的强化对话。

## 3.25 对话页前端状态机

对话页本身也需要状态机。

```text
INITIALIZING
CONNECTING
READY
LISTENING
USER_SPEAKING
TRANSCRIBING
WAITING_AI
PLAYING_AUDIO
INTERRUPTING
RECONNECTING
ERROR
COMPLETED
```

状态说明：

| 状态          | 说明               |
| ------------- | ------------------ |
| INITIALIZING  | 加载场景和历史消息 |
| CONNECTING    | 创建 Realtime 会话并建立 WebRTC |
| READY         | 用户可以输入       |
| LISTENING     | 麦克风已连接并等待语音 |
| USER_SPEAKING | VAD 检测到用户正在说话 |
| TRANSCRIBING  | 正在接收增量或最终字幕 |
| WAITING_AI    | 等待 AI 回复       |
| PLAYING_AUDIO | 正在播放 AI 语音   |
| INTERRUPTING  | 用户插话并取消 AI 未播放回复 |
| RECONNECTING  | 网络中断后重新建立会话 |
| ERROR         | 本轮请求失败       |
| COMPLETED     | 场景练习结束       |

限制规则：

```text
USER_SPEAKING 时禁止重复开启麦克风
WAITING_AI 时允许用户通过语音打断
PLAYING_AUDIO 时检测到用户发言必须进入 INTERRUPTING
COMPLETED 后禁止继续发送普通消息
ERROR 时允许重试
```

## 3.26 可访问性设计

必须支持：

- 键盘操作。
- 清晰焦点状态。
- 按钮文字或 aria-label。
- 录音状态提示。
- 颜色不能作为唯一状态标识。
- 字体缩放。
- 对比度达标。


## 3.27 产品体验原则

### 原则一：练习优先

任何页面都应让用户容易进入练习。

------

### 原则二：减少学习压力

不要一次展示过多错误。

推荐每轮重点展示：

```text
一个最重要问题
一个更自然表达
```

完整错误可以在练习总结中查看。

------

### 原则三：反馈真实

不要无条件表扬。

AI 应根据用户表现给出：

```text
能够被理解
基本完成
表达不完整
需要提示后完成
独立完成
```

------

### 原则四：避免中文依赖

中文解释可以使用，但默认不应覆盖所有英文内容。

------

### 原则五：收藏必须有复习价值

收藏不是一个单纯的爱心按钮。

收藏后需要支持：

```text
复听
跟读
重新练习
查看表达
查看历史
```

------

### 原则六：记录必须服务于成长

日历、报告、错误本不能只展示数据。

每个数据页面都应提供下一步行动：

```text
继续练习
重新复习
练习薄弱场景
```

## 3.29 本章总结

AI Speaking Coach 的产品架构围绕以下三条主线构建：

```text
练习
复习
成长
```

用户最重要的主流程是：

```text
首页推荐
↓
场景详情
↓
对话练习
↓
练习总结
↓
错误和词汇沉淀
↓
日历与报告
↓
再次练习
```

PC 端采用：

```text
左侧导航
+
核心内容
+
上下文右侧面板
```

移动端采用：

```text
底部导航
+
单栏内容
+
Bottom Sheet
```

整个页面设计的核心不是展示功能数量，而是帮助用户：

```text
更快开始说
更少害怕犯错
更容易重复练习
更清楚看到成长
```
